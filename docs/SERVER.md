# Сервер і веб-інтерфейс: запуск

Склад (усе в Docker, файл `docker-compose.yml` у корені):

| Сервіс | Що це | Порт назовні |
|---|---|---|
| `db` | PostgreSQL 16 + TimescaleDB | не публікується |
| `mqtt` | Mosquitto 2 з dynamic security (окремий логін і пароль на кожен модуль) | `MQTT_PUBLIC_PORT` (1883) |
| `server` | Python FastAPI: прийом MQTT, запис у базу, API, WebSocket | не публікується |
| `web` | Caddy: інтерфейс React і проксі `/api` на сервер; на VPS сам отримує HTTPS-сертифікат | `HTTP_PORT` (8080), `HTTPS_PORT` |

## Домашній ПК (Windows, Docker Desktop)

```
cd E:\diploma2
copy .env.example .env      (змініть паролі в .env)
docker compose up -d --build
```

- Інтерфейс: http://localhost:8080, логін і пароль з `ADMIN_USERNAME` / `ADMIN_PASSWORD`.
- У `.env` поставте `PUBLIC_URL=http://<IP ПК у локальній мережі>:8080`, бо за цією адресою модулі завантажують прошивку.
- Для прошивки модулів: `SERVER_URL` = той самий `PUBLIC_URL`, MQTT = `<IP ПК>:1883` без TLS, `PROVISION_TOKEN` = як у `.env`.
- Брандмауер Windows має пропускати вхідні 8080 і 1883.
- Якщо порт 8080 або 1883 уже зайнятий іншою програмою, змініть `HTTP_PORT` або `MQTT_PUBLIC_PORT` у `.env` (і `PUBLIC_URL` відповідно), наприклад `HTTP_PORT=8090`.
- Якщо репозиторій клоновано до появи `.gitattributes` і брокер падає з «set: illegal option -», після `git pull` видаліть `mosquitto/entrypoint.sh` і відновіть його командою `git checkout -- mosquitto/entrypoint.sh` (тоді він буде з закінченнями рядків LF).

## Додавання модуля

1. Зберіть повні образи (`idf.py ... merge-bin`, див. `docs/PROTOCOL.md`, розділ 6.1) і завантажте їх на сторінці «Прошивки» (по одному на ESP32-S3 і ESP32-C3; сайт бере найновіший).
2. Відкрийте «Додати модуль» у Chrome або Edge на комп'ютері, до якого підключено плату (сайт по https або localhost).
3. Введіть Wi-Fi, натисніть «Вибрати порт і прошити», виберіть COM-порт. Сайт визначить чип, запише прошивку, налаштування (Wi-Fi, адреса сервера, MQTT, токен реєстрації) і дочекається, поки модуль з'явиться на зв'язку.

Значення для модуля беруться з `.env`: `PUBLIC_URL`, `MQTT_PUBLIC_HOST` (порожньо = хост із `PUBLIC_URL`), `MQTT_PUBLIC_PORT`, `MQTT_TLS`, `PROVISION_TOKEN`.

## VPS

1. Доменне ім'я, що вказує на VPS.
2. У `.env`: `SITE_ADDRESS=monitor.example.com`, `HTTP_PORT=80`, `HTTPS_PORT=443`, `PUBLIC_URL=https://monitor.example.com`.
3. TLS для MQTT: отримати сертифікат (наприклад, `certbot certonly --standalone -d monitor.example.com` до запуску `web`), потім `MQTT_TLS=true`, `MQTT_PUBLIC_PORT=8883`, `MQTT_CERTS_DIR=/etc/letsencrypt/live/monitor.example.com`. Після оновлення сертифіката: `docker compose restart mqtt`.
4. `docker compose up -d --build`.

## Розробка інтерфейсу

```
cd web
npm install
npm run dev        (http://localhost:5173, запити /api ідуть на сервер на localhost:8000)
```

Сервер окремо: `cd server`, `pip install -r requirements.txt`, змінні з `.env` (`DB_DSN`, `MQTT_HOST`, `MQTT_PORT`), `uvicorn app.main:app --reload`.

## Дані

- Показники зберігаються у вузькій таблиці `telemetry (time, module_id, metric, value)`, тому нові датчики етапу 2 не потребують змін у базі.
- Середні за хвилину і за годину рахує TimescaleDB (continuous aggregates); графіки самі беруть сирі дані (до 3 год), хвилинні (до 10 днів) або годинні.
- Терміни зберігання змінюються на сторінці «Налаштування» (за замовчуванням 7 днів / 90 днів / без обмеження). Сирі дані старші за добу стискаються.
- Запис іде пачками раз на секунду.

## Оновлення прошивки кількох модулів

На сторінці «Модулі» відмітьте плати галочками (галочка в заголовку вибирає всі показані; фільтр «Є нова прошивка» лишає тільки застарілі), виберіть версію і натисніть «Оновити вибрані». Файл під чип кожного модуля (S3 або C3) сервер підбирає сам за версією серед завантажених файлів застосунку. Модулі, що вже на цій версії, без файла під свій чип або не на зв'язку, пропускаються.

Оновлення йде по черзі: наступний модуль стартує, коли попередній перезапустився з новою версією (або сталася помилка чи минув час очікування), і ще через 3 с. Скільки модулів оновлювати одночасно, задає «Налаштування → модулів у хвилі», типово 1 (старе типове 10 при оновленні сервера разово змінюється на 1), бо платам від одного блока живлення шкодить одночасний перезапуск. Над таблицею видно хід (готово, оновлюється, чекають, помилки), у таблиці стан кожного модуля; кнопка «Зупинити» скасовує ще не розпочаті. Стан пакета зберігається в пам'яті сервера (останні 20), після перезапуску сервера зникає, а самі команди лишаються в історії модуля. Біля версії модуля позначка «є X», якщо для його чипа завантажено новішу.

API: `POST /api/commands/bulk` з `{"module_ids": [...], "name": "ota", "params": {"version": "0.5.1"}}`, хід `GET /api/commands/batches/{id}`, зупинка `POST /api/commands/batches/{id}/cancel`.

## Що перевірено і що ні

Перевірено в Docker тестовим MQTT-клієнтом (не реальною платою): реєстрація, статус і Last Will, телеметрія, команди і відповіді, конфігурація інтервалу (модуль, група), завантаження прошивки і видача файла за токеном, групові команди, навантаження 200 модулів × 1 повідомлення/с протягом хвилини (12 000 повідомлень, 48 000 записів, без втрат).

Не перевірено: робота з реальними ESP32, OTA до кінця на платі, TLS на VPS. Сторінку «Додати модуль» перевірено в браузері з імітацією порту (команди info і provision, поява модуля, збереження назви); прошивання через esptool-js з реальною платою не перевірено.
