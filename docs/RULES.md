# Правила автоматизації і сповіщення (етап 3)

Правила перевіряє сервер (`server/app/rules.py`), модулям нічого не потрібно знати про них.

## Правило

| Частина | Варіанти |
|---|---|
| Де діє | усі модулі, група, вибрані модулі |
| Коли спрацьовує | показник поза межею (`>`, `>=`, `<`, `<=`, `=`, `!=`) довше N с; немає зв'язку довше N с; модуль знову на зв'язку; розклад (щодня о ГГ:ХХ у вибрані дні або кожні N хв, час за `Europe/Kyiv`, налаштування `timezone`) |
| Сповіщення | рівень (інформація, попередження, тривога), власний текст з `{module}`, `{value}`, `{unit}`, `{threshold}`, `{rule}` |
| Дії | світлодіод увімк./вимк./блимати, перезапуск, змінити інтервал надсилання, вивести на екран; на модулі, де спрацювало (для розкладу: на всіх модулях правила), або на вказаному модулі |
| Вивести на екран | текст (до 60 символів, можна `{module}`, `{value}`, `{unit}`, `{threshold}`, `{rule}`) на місце 1–4; його показує пункт екрана «Повідомлення правила» з тим самим місцем, нічого не з'являється поверх. Скільки секунд показувати (порожньо — до наступного повідомлення); порожній текст прибирає повідомлення, зручно в «Після повернення в норму». `{module}` — модуль, де спрацювало правило, навіть якщо текст іде на інший модуль. Модуль без зв'язку отримає повідомлення, щойно підключиться |
| Після повернення в норму | ті самі дії (лише для «показник» і «немає зв'язку») |
| Не частіше ніж раз на | пауза між спрацюваннями для одного модуля |

Тривога триває від спрацювання до повернення в норму: для показника умова має бути хибною ті самі N с, для зв'язку модуль має повернутися. Активні тривоги видно на сторінці «Сповіщення» і лічильником у меню (колір за найвищим рівнем); «Підтвердити» прибирає тривогу з лічильника. Після перезапуску сервера активні тривоги відновлюються з бази.

## Канали сповіщень

Інтерфейс показує всі тривоги завжди. Додатково можна додати канали: Telegram (токен бота і ID чату) і вебхук (HTTP POST з JSON `{"text", "level", "kind", "rule_id", "module_id", "value"}`). Кожен канал має мінімальний рівень і вмикач «повідомляти про повернення в норму»; кнопка «Перевірити» надсилає тестове повідомлення.

Щоб додати власний канал, допишіть у `server/app/rules.py` клас-нащадок `Channel` (поля `type`, `title`, `fields` і метод `send`) і додайте його в `CHANNEL_TYPES`. Форма в інтерфейсі будується з `fields` сама.

## Зовнішні тривоги

Інші частини сервера можуть відкрити й закрити тривогу без правила: `rules.engine.raise_external(module_id, key, level, text)` і `rules.engine.clear_external(module_id, key)`. Так можна показувати тривоги, які надсилає сам модуль (гібридний режим, етап 2).

## API

`GET/POST /api/rules`, `PUT/DELETE /api/rules/{id}`, `POST /api/rules/{id}/enabled`, `POST /api/rules/{id}/run` (виконати правило за розкладом зараз), `GET /api/rules/meta`;
`GET /api/alerts?active=true`, `POST /api/alerts/{id}/ack`, `POST /api/alerts/ack-all`;
`GET/POST /api/channels`, `PUT/DELETE /api/channels/{id}`, `POST /api/channels/{id}/test`.
Через WebSocket приходить `{"type": "alert", "data": {...}}` при кожній зміні тривоги.
